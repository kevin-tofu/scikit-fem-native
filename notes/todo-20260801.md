# Production-readiness TODO — 2026-08-01

## Current assessment

`skfem-native` (`import skfemntv`) is no longer a toy implementation.  It is
usable today as a focused assembly engine for controlled meshes and workflows
such as internal research, reduced-order model generation, constitutive-model
development, and nonlinear assembly experiments.

Evidence available as of 2026-08-01:

- 320 unit tests;
- numerical comparisons with equivalent scikit-fem forms;
- linear elasticity, Neo-Hookean hyperelasticity, J2 plasticity, and a
  Standard Linear Solid;
- Tet, Hex, Wedge, and Pyramid volume/facet assembly, including higher-order
  Tet10 and Hex27;
- state commit/rollback for history-dependent materials;
- nonmatching surface integration and supermesh search;
- race-free colored CSR scatter;
- 4.60x R+K speedup from one to eight threads for a 5184-DoF Hex8 benchmark;
- isolated sdist/wheel builds and `twine check` passing;
- no runtime dependency on or fallback to scikit-fem.

This does **not** yet make the project a production-ready general-purpose FEM
platform.  The following work is ordered by risk rather than feature appeal.

## P0 — Geometry validation and diagnostics

The original issue was use of the absolute Jacobian determinant without
scale-aware validation.  A uniformly negative local orientation is valid for
H1 assembly and occurs in canonicalized scikit-fem-compatible connectivity, so
it is accepted and reported.  Singular/near-singular points and a sign change
within one curved element are invalid.

- [x] Reject `abs(det(J)) <= scale-aware tolerance`.
- [x] Reject determinant sign changes within an element.
- [x] Define a scale-aware default tolerance; avoid a single absolute epsilon.
- [x] Report element ID, quadrature-point ID, determinant, and tolerance in an
  error.
- [x] Expose minimum/maximum/scaled determinant, worst element, and negative
  orientation count as Basis diagnostics.
- [x] Add a Jacobian condition-number diagnostic.
- [x] Detect internal inversion of curved Tet10 geometry even when corner
  orientation appears valid.
- [x] Add the corresponding internally inverted Hex27 regression case.
- [ ] Define explicit `error`, `warn`, and diagnostic-only policies.
- [ ] Test valid orientation, reversed connectivity, near-collapse, curved
  internal inversion, and coordinates at very small/large physical scales.

Production gate: an invalid mesh must fail before assembly and identify the
offending element without requiring a debugger.

## P0 — Large-scale memory behavior

Current committed nonlinear parallel results reach 5184 DoFs.  This verifies
thread execution but is not enough to establish production memory behavior.
The element-to-CSR scatter map grows approximately with
`elements * local_dofs**2`, which is especially important for Hex27.

- [ ] Sweep at least 10k, 100k, and where practical 1M DoFs.
- [ ] Measure Basis construction peak RSS.
- [ ] Measure CSR pattern, values, scatter map, coloring, geometry tables, and
  material-state storage separately.
- [ ] Confirm repeated assembly performs no size-dependent allocation.
- [ ] Add a preflight memory estimate before constructing large assemblers.
- [ ] Exercise Tet4, Tet10, Hex8, Hex27, and Wedge6 separately.
- [ ] Record platform, CPU affinity, RAM, compiler, build type, and thread count
  with every result.
- [ ] Establish documented safe problem sizes for typical workstation memory.

Production gate: a user should be able to estimate whether assembler creation
will fit in memory before the allocation begins.

## P0 — Reentrancy and thread-safety contract

Element assembly is internally parallel, but a `NativeAssembler` also reuses
owned residual and tangent buffers.  Concurrent calls on the same instance
must not be assumed safe until a contract is implemented and tested.

- [ ] Document whether every public assembler is reentrant.
- [ ] Reject overlapping calls on a non-reentrant instance, or provide isolated
  per-call workspaces.
- [ ] Make `evaluate_into` the recommended path for caller-owned storage.
- [ ] Consider an explicit `AssemblerWorkspace` or cheap assembler clone.
- [ ] Test concurrent independent assembler instances.
- [ ] Test concurrent calls to one instance according to the chosen contract.
- [ ] Document interaction with OpenMP/BLAS/PETSc thread pools and CPU affinity.

Production gate: concurrent behavior must be deterministic, documented, and
covered by tests rather than depending on caller convention.

## P1 — Compatibility boundaries

The goal is a documented scikit-fem-compatible subset, not complete API
coverage.  `import skfemntv as skfem` should therefore be advertised only for
forms and spaces inside that subset.

Known or intentional gaps include:

- Line meshes/elements;
- H(div), H(curl), plate, Hermite, and other specialized elements;
- normal-oriented facet queries;
- composite elements containing discontinuous fields;
- custom `FacetBasis` mapping and DOF objects;
- some Python operations that cannot be lowered to native form terms;
- complete scikit-fem utility, solver, and condensation APIs.

- [ ] Maintain a machine-tested compatibility matrix.
- [ ] Add one expected-success and expected-failure test for every documented
  category.
- [ ] Ensure unsupported operations raise `UnsupportedNativeForm` or a precise
  capability error, never silently change meaning.
- [ ] Decide whether Line/P1/P2 assembly is valuable enough to add.

Production gate: unsupported code must fail early and predictably.

## Scope that should remain out of core

The following are not required for the assembly engine itself to be practical:

- linear/nonlinear solver policy;
- contact, mortar, or Nitsche formulation selection;
- pressure pinning and condensation policy;
- automatic fallback to scikit-fem;
- mandatory PETSc or third-party C++ tensor dependencies.

These should be demonstrated through integration examples while keeping the
core focused on geometry, form lowering, constitutive updates, and assembly.

## Recommended execution order

1. Geometry determinant validation and diagnostics.
2. 100k-DoF memory/scaling audit with preflight estimates.
3. Reentrancy/thread-safety contract.
4. Merge rename, version bump, cross-platform wheel validation, and release.
5. Numerical/refinement and supermesh robustness expansion.
6. Only then broaden elements or add further constitutive models based on real
   user demand.
