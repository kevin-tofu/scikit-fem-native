# Assembly benchmark — 2026-07-31

Environment:

- Intel Core i9-9900K, 8 physical cores; current engine is single-threaded
- GCC 11.4.0 with release flags
- Python 3.12.12
- NumPy 2.5.1, SciPy 1.18.0, scikit-fem 12.0.2
- second-order quadrature requested for both implementations
- median of seven measured calls after two warm-up calls
- initialization and fixed-CSR construction excluded

The linear comparison includes tangent assembly and residual evaluation on
both sides.  `skfemntv` evaluates both in one native traversal; the scikit-fem
reference assembles its elasticity form and evaluates `K @ u`.

| Topology | Elements | DOFs | NNZ | skfemntv | scikit-fem | Speedup |
|---|---:|---:|---:|---:|---:|---:|
| Tet4 | 750 | 648 | 22,014 | 0.232 ms | 32.398 ms | 139.6× |
| Tet4 | 4,374 | 3,000 | 114,462 | 1.362 ms | 126.798 ms | 93.1× |
| Tet4 | 13,182 | 8,232 | 329,598 | 5.062 ms | 431.775 ms | 85.3× |
| Hex8 | 64 | 375 | 19,773 | 0.068 ms | 41.021 ms | 605.0× |
| Hex8 | 343 | 1,536 | 95,832 | 0.335 ms | 106.245 ms | 317.3× |
| Hex8 | 1,000 | 3,993 | 268,119 | 0.983 ms | 225.540 ms | 229.4× |

Equivalent Neo-Hookean residual and analytical tangent forms were also
implemented using scikit-fem.  Their output agrees with `skfemntv` for both Tet4
and Hex8 to approximately machine precision.

| Topology | Elements | DOFs | skfemntv residual | skfemntv residual + tangent | scikit-fem residual + tangent | Speedup |
|---|---:|---:|---:|---:|---:|---:|
| Tet4 | 750 | 648 | 0.239 ms | 2.180 ms | 301.875 ms | 138.5× |
| Tet4 | 4,374 | 3,000 | 1.357 ms | 12.800 ms | 1,668.589 ms | 130.4× |
| Hex8 | 64 | 375 | 0.050 ms | 1.085 ms | 267.692 ms | 246.7× |
| Hex8 | 343 | 1,536 | 0.236 ms | 5.816 ms | 1,073.077 ms | 184.5× |
| Hex8 | 1,000 | 3,993 | 0.678 ms | 16.870 ms | 2,990.194 ms | 177.2× |

These measurements confirm that the coarse-grained native boundary and reused
CSR scatter map are working as intended.  The native tangent path costs about
9.4 times the residual-only path for Tet4 and 24.9 times for the largest Hex8
case.  This identifies analytical tangent evaluation and scatter as the next
native optimization target; Python-boundary overhead is already negligible.

The largest attempted scikit-fem Tet4 nonlinear case did not complete in the
available benchmark process, so the default benchmark stops at 4,374 tetrahedra.
Memory profiling and kernel-versus-scatter instrumentation remain future work.

## Cross-basis contraction profiling

`benchmarks/cross_assembly.py` uses a synthetic overlapping four-node
cross-basis workload with three components, three physical gradient
directions, and six quadrature points.  It measures the normal fused assembly
and the identical contraction traversal without CSR scatter.  Their
difference is reported as a scatter estimate; it is an estimate because the
production loop intentionally fuses contraction and scatter.

The generic baseline traversed all component and spatial direction pairs,
including entries known to be zero for scalar coefficients:

| Entities | Contraction | Baseline total | Baseline contract share |
|---:|---|---:|---:|
| 10,000 | value–value | 57.145 ms | 84.6% |
| 10,000 | value–gradient, dense tensor | 75.550 ms | 82.9% |
| 10,000 | gradient–gradient | 162.952 ms | 86.1% |

Adding dependency-free scalar-specialized kernels gives:

| Entities | Contraction | Optimized total | Speedup | Contract share |
|---:|---|---:|---:|---:|
| 10,000 | value–value | 7.953 ms | 7.2× | 49.6% |
| 10,000 | value–gradient, dense tensor | 65.721 ms | 1.1× | 93.0% |
| 10,000 | gradient–gradient | 9.674 ms | 16.8× | 62.0% |

This shows that an external SIMD backend is not the first optimization for
scalar forms.  The remaining plausible SIMD target is a genuinely dense
mixed value–gradient tensor, where contraction still accounts for about 93%
of total assembly time.  CSR scatter is now material for the scalar paths.

Reproduce with:

```sh
python benchmarks/assembly.py
python benchmarks/cross_assembly.py
```

## Native planar supermesh construction

`benchmarks/supermesh_builder.py` builds two coincident structured triangle
surfaces with opposite cell diagonals.  The native path includes AABB sweep,
polygon clipping, fan triangulation, quadrature generation, NumPy result
creation, and reusable cross-assembler initialization.

| Cells/axis | Triangles/side | Cartesian pairs | AABB candidates | Integration triangles | Build | Output |
|---:|---:|---:|---:|---:|---:|---:|
| 16 | 512 | 262,144 | 8,464 | 1,024 | 3.57 ms | 0.88 MB |
| 32 | 2,048 | 4,194,304 | 35,344 | 4,096 | 14.27 ms | 3.54 MB |
| 64 | 8,192 | 67,108,864 | 144,400 | 16,384 | 74.21 ms | 14.16 MB |
| 128 | 32,768 | 1,073,741,824 | 583,696 | 65,536 | 418.37 ms | 56.62 MB |

Construction scales with the retained broad-phase and output sizes rather
than the Cartesian pair count.  Intersection records accumulate in reserved
typed C++ vectors and are copied into their final NumPy arrays once.

Reproduce with:

```sh
python benchmarks/supermesh_builder.py 16 32 64 128
```
